# 01 — High-Level Architecture & Tech Stack

## Architecture at a glance

```
┌────────────────────────────┐        ┌──────────────────────────────┐
│  client/  (React + Vite)   │  HTTP  │  server/  (Express + TS)     │
│  - curriculum browser      │ ─────▶ │  - REST API  /api/*          │
│  - markdown reader         │  JSON  │  - better-sqlite3            │
│  - React Flow diagrams     │        │  - serves data/app.db        │
│  - notes & progress UI     │        └──────────────┬───────────────┘
└────────────────────────────┘                       │
                                          ┌──────────▼───────────┐
   scripts/ (run at build/authoring time) │  data/app.db (SQLite)│
   - parse primer → primer-corpus.json    └──────────▲───────────┘
   - compile topic-map → curriculum.json             │
   - validate diagram JSON                           │
   server/ npm run seed  ────────────────────────────┘
```

Three independent parts. The **scripts** pipeline turns source material into `content/curriculum.json`; the **server** seeds that file into SQLite and exposes a REST API; the **client** is a pure consumer of that API.

The curriculum is organised **by topic**, not by source — see [docs/06-topic-model.md](06-topic-model.md).

## Tech stack (all open-source)

| Layer | Choice | License | Why (esp. for small AI coder models) |
|---|---|---|---|
| Frontend framework | React 18 + TypeScript + Vite | MIT | Most-represented stack in training data; fewest hallucinated APIs |
| Styling | Tailwind CSS v3 + `@tailwindcss/typography` | MIT | Utility classes keep styling inside JSX. Semantic tokens (`canvas`/`surface`/`raised`/`line`/`ink`) map to CSS variables, so light/dark is one class switch |
| Client state | Zustand | MIT | One store file, no boilerplate, no context wiring mistakes |
| Routing | React Router v6 | MIT | Standard |
| Markdown render | react-markdown + remark-gfm | MIT | Renders primer content incl. tables safely (no `dangerouslySetInnerHTML`) |
| Diagrams | **React Flow (`@xyflow/react` v12)** | MIT | See [docs/04-diagrams.md](04-diagrams.md) for full evaluation |
| Icons | lucide-react | ISC | Ready-made server/database/cloud icons → no hand-drawn SVG tasks |
| Backend | Node 20 + Express 4 + TypeScript | MIT | Simplest possible REST layer; hugely familiar to all models |
| Validation | zod | MIT | Runtime request-body validation with TS inference |
| Database | SQLite via better-sqlite3 | MIT | Local single-user app: zero config, synchronous API (no async/await bugs), plain SQL — schemas in docs are copied verbatim |
| Diagram schema validation | ajv | MIT | Validates hand-authored diagram JSON against our JSON Schema |

**Deliberate exclusions:** no ORM (Prisma/Drizzle add a schema-indirection layer where small models drift from the documented DDL), no monorepo tooling (client and server are two plain npm packages), no auth (local single user), no CSS-in-JS.

> The node components are grouped by shape (`IconNodes.tsx` for the 14 icon-based kinds,
> `SpecialNodes.tsx` for service/text_box/table) rather than one file per kind as the original task
> files proposed — fourteen near-identical six-line files was noise. `nodes/index.ts` holds the
> registry and a `Record<NodeKind, unknown>` check that fails compilation if a kind loses its renderer.

## Design system

All visual decisions live in `client/tailwind.config.js` + `client/src/index.css`, never in ad-hoc
utility strings:

- **Semantic colour tokens** — `canvas`, `surface`, `raised`, `line`, `ink`, `ink-muted`, `ink-faint`
  resolve to CSS variables. `.dark` on `<html>` swaps every value at once.
- **Dark mode** is class-based, seeded from `prefers-color-scheme`, persisted to `localStorage`, and
  toggled from the top bar (`useThemeStore`, initialised in `main.tsx` before first paint).
- **Track accents** come from the database and are injected as the `--accent` CSS variable on the page
  root, so one topic's colour drives its hero, section labels, controls, and sidebar marker.
- **Reading column** uses the `.prose-reader` component class: serif body at 17px/1.75 with sans
  headings — UI chrome stays sans.

## API surface (summary — exact contracts in docs/02)

| Method + path | Purpose |
|---|---|
| `GET /api/health` | liveness check |
| `GET /api/curriculum` | full tree: tracks → topics (+ per-topic progress rollup) |
| `GET /api/topics/:idOrSlug` | one topic: sections with markdown, topic links (+completion), diagrams (+viewed), prev/next |
| `GET /api/diagrams/:id` | one diagram spec JSON |
| `PUT /api/progress/section/:id` | set section status |
| `PUT /api/progress/link/:id` | set external-link completed flag |
| `PUT /api/progress/diagram/:id` | mark diagram viewed |
| `GET /api/progress/summary` | totals per track for the dashboard |
| `GET/POST /api/notes`, `PUT/DELETE /api/notes/:id` | notes CRUD (anchored to topic OR section) |
| `GET /api/dev/diagram-files`, `GET /api/dev/diagram-file?name=` | authoring preview: read raw diagram files |

Server runs on **port 4000**; Vite dev server on **5173** proxies `/api` → `http://localhost:4000` (configured in `vite.config.ts`), so the client code always calls relative `/api/...` paths.
